## Current Research Question

We are trying to understand what GAP's Pi3/future-latent branch is actually using:

1. **Full-scene geometry hypothesis**: GAP benefits because dense Pi3 tokens encode broad 3D scene geometry.
2. **Hand-object interaction-region hypothesis**: GAP benefits mainly from geometry around hands/end-effectors and manipulated objects, not from the whole scene.

The current local data does **not** contain true object/hand masks or object poses, so the current experiments can weaken or support the full-scene story, but they cannot fully prove a true object-centric interaction-region mechanism yet.

Important nuance:

RoboTwin source code appears to support `actor_segmentation` and `mesh_segmentation` through `Camera.get_segmentation()` and `Base_Task.get_obs()`, but the downloaded `demo_clean` HDF5 files were collected with those fields disabled. The local `scene_info.json` only stores episode-level object identity, not per-frame actor poses. `_traj_data/*.pkl` stores left/right joint paths, not object trajectories.

Therefore, true object/hand masks are not available in the existing dataset, but may be recoverable by replaying saved seeds/trajectories with `actor_segmentation: true`.

## Current Interpretation

Strongest defensible conclusion:

> On `place_dual_shoes` with 50 demos and seed 0, full-scene dense Pi3/future latent is not necessary for the best observed eval score. Future-latent supervision may still help inside Pi3-based policies, but the current EEF-region proxy is too weak to identify a true interaction-region mechanism.

Why this weakens the full-scene geometry hypothesis:

- `dino_only` is best: `8/50`, while `vanilla` is `4/50`.
- `pi3_pooled` is competitive: `6/50`, which weakens a strict dense full-token requirement.
- `pi3_dropout` matches vanilla: `4/50`.
- `pi3_non_eef_region` is close to `pi3_eef_region`: `5/50` vs `6/50`.

Why future-latent supervision may still matter:

- `no_future` is low: `1/50`, below vanilla.
- This suggests future-latent supervision can help within Pi3-based policies.
- But because `dino_only` beats vanilla, this cannot be interpreted as proof that future Pi3 geometry is the main useful mechanism.

Why this does **not** prove hand-object interaction-region causality:

- `pi3_eef_region` is only one success above `pi3_non_eef_region`.
- EEF projection is not a true object-hand mask.
- Current dataset lacks object masks, robot/hand masks, object pose, object keypoints, and contact.

## Important Caveats

- This is only one task.
- This is one training seed.
- The current run used 50 demos, not the paper's typical 100-demo setup.
- Training was stopped at 200 epochs, not 300.
- Eval has 50 rollouts per variant, better than 10, but still small for fine-grained differences.
- Absolute success rates are low, so small differences should be treated cautiously.
- The downloaded HDF5 data does not expose the true supervision needed for object-centric masking.

## What Was Just Being Investigated Before This Handoff

We began checking whether RoboTwin/SAPIEN could provide the missing true masks by replaying data.

Findings from source inspection:

- `envs/camera/camera.py` has `Camera.get_segmentation(level="mesh"|"actor")`.
- `Base_Task.get_obs()` supports:
  - `data_type.mesh_segmentation`
  - `data_type.actor_segmentation`
- `task_config/demo_clean.yml` currently sets both segmentation flags to `false`.
- `scene_info.json` gives episode-level object identity such as shoe model ID and shoe-box ID.
- `_traj_data/episode*.pkl` stores `left_joint_path` and `right_joint_path`, but not object trajectories.
- Because saved seeds and joint paths exist, a plausible next step is to replay episodes with `actor_segmentation: true` and collect segmentation/masks without replanning.

One attempted SAPIEN runtime probe was not completed because sandbox execution could not see CUDA, and the follow-up escalated run was rejected. No new runtime evidence was produced by that probe. The source-level evidence above remains useful, but it should be verified with a small replay probe in a new conversation.

## Recommended Next Step

Do **not** keep training more full-scene variants on the same single task first.

Instead, prioritize verifying whether true object/robot masks can be extracted from RoboTwin replay:

1. Create a small segmentation replay probe for `place_dual_shoes`, episode 0 only.
2. Load `seed.txt` and `_traj_data/episode0.pkl`.
3. Set `need_plan=false`, `save_data=false`, `actor_segmentation=true`, `mesh_segmentation=true`, and minimal cameras first.
4. Replay `play_once()` using saved joint paths.
5. Inspect raw `camera.get_picture("Segmentation")` labels, not only RGB-colored segmentation images.
6. Map actor-level labels back to SAPIEN actor names if possible.
7. If actor labels can identify `left_shoe`, `right_shoe`, `shoe_box`, and robot links, generate true Pi3 token masks.
8. Add real variants:
   - `pi3_object_region`
   - `pi3_robot_region`
   - `pi3_object_hand_region`
   - `pi3_non_object_hand_region`
9. Re-run at least the key controls:
   - `vanilla`
   - `dino_only`
   - `no_future`
   - `pi3_pooled`
   - true object-hand region variants
